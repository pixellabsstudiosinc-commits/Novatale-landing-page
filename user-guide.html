NovaTale — Complete User Guide Everything you need to build, preview, and ship a visual novel — using Moonlit Signals as the running example.

1.Welcome to NovaTale

NovaTale is a desktop visual-novel creator by PixelLabs. It is designed for storytellers who want to build branching, media-rich visual novels with very little or no code. Instead of writing a script file first, you assemble your project visually: import artwork, write dialogue, connect scenes on a graph, and export the finished game as a standalone desktop application for Windows, macOS, and Linux.

🖼️
Screenshot: NovaTale welcome screen with “Create New Project” and “Open Existing Project” buttons
user-guide-assets/01-welcome-screen.png

What you can build

  • Image, video, and no-media scenes with dialogue boxes and named speakers
  • Branching narratives driven by conditional logic over variables and character metadata
  • Character profiles with portraits, relationships, metadata, and runtime-renameable names
  • Custom button styles reused across scenes and the main menu
  • A custom main menu on a 1920×1080 design canvas
  • Save / load system with 10 manual slots, a quick-save slot, and an auto-save slot
  • One-click export to Windows .exe, macOS .dmg, and Linux .AppImage

Who this guide is for

This guide assumes no programming background. Wherever NovaTale lets you write a small expression (for example, a branch condition), the expression syntax is explained with worked examples. Everything else is just filling in forms, clicking buttons, and connecting nodes on a graph.

First launch

  1. Install NovaTale using the installer you received (DMG on macOS, EXE on Windows, AppImage on Linux).
  2. Launch the application. On the very first launch you will see the activation screen (covered in Section 4).
  3. Choose Try Demo Mode to explore with limits, or enter a license key to unlock everything.
  4. After activation you are taken to the Welcome screen, where you can create or open a project.
Note NovaTale stores your projects in a local SQLite database managed by the application. You do not edit project files directly — everything is done through the editor screens.

3.The Sample Story — Moonlit Signals

Throughout this guide we will build Moonlit Signals, a tiny mystery visual novel. It is small enough to fit in a few scenes but uses every NovaTale feature at least once.

🌙
Concept art: Moonlit Signals — rainy school library at night
user-guide-assets/22-player-dialogue.png

Premise

The player joins Mira in the school library during a rainstorm. A strange signal appears on the astronomy club receiver. The player can choose whether to follow Mira to the rooftop, stay behind and investigate the library, or try to convince Ren (the skeptical classmate) to help.

Cast

  • Player — renameable protagonist (default display name: You)
  • Mira — astronomy club student. Metadata: trust, affection, knowsSignal.
  • Ren — skeptical classmate. Metadata: trust.

Variables

NameTypeDefaultUse
signalStrengthnumber0Mystery progress
hasKeycardbooleanfalseUnlocks the rooftop route
routestringlibraryCurrent story route
trustnumber10Global trust score

Scenes

  1. Main Menu — rooftop observatory background, New Game / Load / Preferences / Quit buttons.
  2. Library Signal — image scene, Mira speaks, branch buttons appear.
  3. Rooftop Door — conditional on hasKeycard === true; action: signalStrength += 20.
  4. Library Investigation — action: trust += 5; Mira.trust += 10.
  5. Signal Revelation — conditional on signalStrength >= 50; ending scene.

Every later section in this guide adds the next piece of Moonlit Signals so you can replicate it end-to-end while you read.

Demo Mode

Click 🎮 Try Demo Mode. The button shows a spinner labelled Activating Demo… and you are taken to the Welcome screen. Demo Mode lets you use every editor screen with the following limits:

  • Max 2 projects total
  • Max 3 characters per project
  • Max 10 scenes per project

  • 🛒 Purchase License — opens the Gumroad page in your browser

License Key

  1. Enter your key in the format XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX.
  2. Click Activate License (or press Enter).
  3. NovaTale verifies the key online and registers this device.
  4. On success, you see Activation Successful! and are redirected after ~1.5 seconds.

Basic Information

FieldRequiredNotes
Character NameYesUsed as the speaker label and as the key in dialogue expressions (e.g. {Mira.trust}).
GenderNoEmpty / Male / Female / Non-binary / Other.

Appearance

  • Character Portrait — click to upload. Supported: jpg, jpeg, png, gif, bmp, webp. The image is stored as a base-64 data URI inside the project, so you do not need to keep the source file around. A remove button clears the image.
  • Name Color — colour picker plus hex input (default #4CAF50). The speaker name in the dialogue box uses this colour.

Special Properties

  • Mark as Protagonist — only one protagonist per project. If you tick this on a second character, NovaTale blocks the save and tells you which character is the existing protagonist.
  • Allow players to rename this character — when ticked, an extra field appears called Default Display Name. This is the name shown to the player at game start; the player can override it via the rename prompt or the in-game Status Screen.

Additional Data (Metadata)

Metadata is the most powerful part of a character. Add any number of key/value pairs by typing a key, typing a value, and clicking Add. Each entry appears as a removable chip. Metadata becomes available throughout the project as CharacterName.fieldName — usable in dialogue expressions, branch conditions, and branch actions.

Tip Treat numeric metadata as game stats. trust, affection, love, health, mana, gold, strength, intelligence — these all get nice auto-icons on the in-game Status Screen.

11.Dialogue Expressions

Inside any dialogue text — and any place that accepts an expression — anything between { and } is evaluated as a JavaScript-style expression at runtime. This is how you make dialogue react to player choices.

What you can access

ContextSyntaxExample
Variablesname{signalStrength}
Character propertiesCharacter.name, Character.gender{Mira.name}
Character metadataCharacter.fieldName{Mira.trust}
Custom relationship labelrel.CharacterNameMira is my {rel.Mira}.
Arithmetic+ - * / %{100 - signalStrength} to go
Comparison=== !== > < >= <={trust > 50 ? "ally" : "stranger"}
Logical&& || !{hasKeycard && signalStrength > 30}
Ternarycond ? a : b{hasKeycard ? "rooftop opens" : "door stays shut"}

Worked examples (Moonlit Signals)

Mira's trust is currently {Mira.trust}.
The signal strength is {signalStrength}. You need {Math.max(0, 50 - signalStrength)} more to break the code.
{hasKeycard ? "The rooftop door unlocks with a click." : "The door refuses to open."}
Mira is my {rel.Mira}.
{Mira.trust >= 40 && hasKeycard ? "Mira hands you the keycard." : "Mira hesitates."}

Error behaviour

  • Mismatched braces are detected before evaluation. The error tells you how many opening vs closing braces it found.
  • Empty expressions ({}) render as an empty string.
  • Runtime errors (e.g. referencing a variable that doesn't exist) cause the expression to render as-is, surrounded by its braces, and the error is logged to the console.
Tip Always test important dialogue lines in Play Preview. If something looks off, open the dev console (View → Toggle Developer Tools in dev mode) to see the underlying error.

Scene nodes

user-guide-assets/16-scene-graph-node.png

Each scene appears as a node with:

  • A header showing the media-type icon and scene name
  • Feature badges — 💬 Dialogue if a speaker is set, 🎵 BGM if BGM is set
  • A short preview of the dialogue text (first 50 characters)
  • An Edit button at the bottom
  • Eight connection handles (one on each side, in/out) so you can connect from any edge

Drag a node to reposition it. The new position is saved automatically when you release.

Edges (branches)

  • Solid amber edge = a default (unconditional) branch.
  • Dashed indigo edge = a conditional branch (animated for emphasis).
  • The edge label shows the transition type and, if any, the condition expression — e.g. fade (signalStrength >= 50).
  • Click an edge to edit the branch.
  • Drag an edge's endpoint to reconnect it to a different node.

Starting scene detection

NovaTale automatically picks the starting scene as: the scene with no incoming branches and at least one outgoing branch. If no such scene exists, you cannot preview or export the project — you will be told to fix it.

Watch out Self-loops are blocked (“Cannot connect a scene to itself!”) and duplicate connections between the same two scenes are also blocked (“A branch between these scenes already exists!”).

13.Branches

A branch is a directed connection from one scene to another. Branches carry the transition effect, optional condition, optional state-changing action, and optional button display.

Open the Branch form by either:

  • Connecting two nodes in the Scene Graph by dragging from one handle to another, or
  • Clicking an existing edge.
🔀
Screenshot: Branch form — “Library Signal → Library Investigation”
user-guide-assets/17-branch-form.png

Transition

FieldNotes
Transition TypeFade · Dissolve · Slide Left · Slide Right · Wipe · None.
Duration (ms)Slider 100–2000 ms in 100 ms steps, default 500 ms. Hidden when Transition Type is None.

Logic — Condition and Actions

FieldNotes
ConditionOptional. JavaScript expression. The branch can be taken only if this evaluates to true. Empty means the branch is always available.
ActionsOptional. JavaScript code that runs the moment the branch is taken — used to mutate variables or character metadata. Statements separated by ;.
Default BranchCheckbox. The default branch is used as a fallback when no other branch's condition matches.

Examples — conditions

signalStrength >= 50
Mira.trust > 40 && hasKeycard === true
route === "rooftop"

Examples — actions

signalStrength += 10;
trust += 5;
Mira.trust += 15;
Mira.knowsSignal = true;
route = "rooftop";

Button Configuration (optional)

If you add Button Text, this branch becomes a clickable button shown to the player. If Button Text is empty, the branch auto-advances (after the dialogue plays out, the engine follows the branch automatically).

FieldNotes
Button TextOptional. Supports template expressions (e.g. Trust Mira ({Mira.trust})).
Button StyleOptional. Pick from your reusable styles (Section 14). If empty, the engine uses default styling.
Pattern Use conditions without button text to silently fork the story based on state. Use button text without conditions for plain player choices. Combine both for conditional choices (e.g. a button that only appears when hasKeycard === true).

Deleting a branch

Open the branch form by clicking the edge, then click the 🗑️ Delete Branch button at the bottom right. A confirmation modal shows the branch's source, target, transition, and condition. Click Delete to confirm.

Audio behaviour

The player picks the BGM in this order:

  1. The current scene's BGM, if set.
  2. Otherwise, the BGM already playing carries forward.
  3. Otherwise, the project's Global BGM (Preferences).
  4. Otherwise, silence.

Voice audio plays once when a dialogue line appears and stops on advance. SFX trigger from branch actions or scene actions when used.

18.Save & Load

💾
Screenshot: Save / Load UI showing 10 manual slots + quick + auto
user-guide-assets/25-save-load.png

Slots available

  • 10 manual slots — Slot 1 through Slot 10.
  • 1 quick-save slot — written by F5, read by F9.
  • 1 auto-save slot — exists in the UI but the automatic write-on-transition is not fully wired in the current build; you can save manually into it.

What a save contains

  • Current scene ID
  • All game variables
  • Scene history (every visited scene)
  • Custom character names (from rename prompts)
  • Encountered characters (to avoid re-prompting relationship labels)
  • Forward and reverse relationship labels
  • Character metadata (current values of trust, affection, etc.)
  • Total play time
  • The speaking character and scene name (for display in the save slot card)

Where saves live

Saves are written to the player's local storage on the device running the game. Each project's saves are separate. Save thumbnails are modelled in the data but actual screenshot capture is not yet implemented; slot cards currently show “No Preview”.

Loading from the main menu

The Continue button loads the most recent quick or auto save. Load Game opens the slot selector. Loading drops the player directly into the saved scene.

What happens during export

⏳
Screenshot: Export progress overlay showing stage messages
user-guide-assets/30-export-progress.png
  1. Validate game name, platforms, and that the project has a valid starting scene.
  2. Gather all scenes, characters, branches, variables, relationships, button styles, main menu config, and assets.
  3. Transform absolute asset paths into export-friendly filenames and create a manifest.
  4. Write game-data.json — a single JSON file containing your entire project.
  5. Copy the standalone player template, all assets, and a package.json with your game's name into the output folder.
  6. Install the build dependencies and invoke electron-builder for each selected platform.
  7. Produce the platform installers/packages in the output's dist/ subfolder.

Total time is typically 5–10 minutes depending on platform count, asset size, and your machine.

Output structure

├── index.html           # Player UI shell

Testing the build

  • Run the produced installer on the target platform.
  • Run through New Game → save → load → quit to confirm the save/load cycle works.

21.Known Limits & Coming-Soon Features

NovaTale is a substantial creator tool, but a few areas deserve clear notes:

  • Scene choices are modelled in the data layer and supported at runtime, but the primary authoring flow you should rely on is the Scene Graph + branches system.
  • Gallery, Extras, and Credits main-menu buttons are designable but currently behave as “coming soon” placeholders unless you wire them up.
  • Save thumbnails are modelled but screenshot capture is not implemented yet; slot cards show “No Preview”.
  • The Auto Save slot exists in the UI but the always-on auto-save trigger is not wired up — you can still save manually into it.
  • The in-game history log (replay previously read dialogue) is not implemented yet.
  • Branch logic expressions are powerful but should be tested carefully in Play Preview — wrong syntax silently fails (the expression renders as-is and logs to the console).
  • Some confirmation dialogs still use native browser confirms instead of styled modals.
  • Background video on the main menu is supported by the form but rendering is partial in the current build.

22.Best Practices

  • Name variables clearly — short and unambiguous (trust, gold, route, hasKeycard).
  • Pick character names early and stick with them — every reference in expressions uses the character name as the key.
  • Use character metadata for per-character stats and variables for global story state.
  • Test important branches after every logic change. Use Play Preview, walk through different routes.
  • Keep your source assets in stable folders while building. Move them only after the project is exported.
  • Always have one clear starting scene — no incoming branches, at least one outgoing branch.
  • Create reusable button styles in the Button Designer rather than styling each button separately.
  • Preview before export. Exports take 5–10 minutes per platform — much faster to iterate in the preview.
  • Use a default branch per source scene as a safety net so the game never stalls when no condition matches.
